== Introdução

[role = justificado]
Uma dos grandes pontos em uma feira de ciência e o sistema de votação para eleger o melhor projeto 
pensando nisso este sistema possui como principal ponto a coleta e apresentação da votação de forma intuitiva 
o mesmo conta com uma aplicação em nuvem que faz o armazenamento e processamento dos dados, e uma aplicação

== Visão geral deste documento
Este documento possui como finalidade apresentar os requisitos funcionais e não funcionais da aplicação assim 
como seus principais usuários e o nível de prioridade de cada requisito, estando separado entre:

* *Descrição Geral do Sistema:* Apresentação previa sobre o sistema e suas funcionalidades assim como os públicos
que serão abordados no mesmo, uma classificação de cada um e como os mesmo irão interagir com o sistema.

* *Requisitos Funcionais:* Definição das funcionalidades que o sistema deve apresentar, com sua identificação,
ator principal da funcionalidade, nível de prioridade, pré-condições e entradas necessárias, assim como saídas e pós-condições.

* *Requisitos Não Funcionais:* Apresenta todos os requisitos não funcionais que o sistema deve atender, como desempenho, segurança, usabilidade, entre outros.

== Identificação dos requisitos
Para a identificação dos requisitos foram utilizadas suas devidas categorias, usando uma abreviação da mesma, como por 
exemplo:

 * *RF* - Requisitos Funcionais

 * *RNF* - Requisitos Não Funcionais

Já para identificar suas o número a qual tal funcionalidade pertence, foi utilizado um sistema numérico onde cada casa numérica representa algo, como no exemplo:

*RF001*

* *Primeira casa decimal:* representa a camada a qual a funcionalidade pertence, exemplo: segurança, apresentação

* *Segunda casa decimal:* representa a categoria de atores que a usam, exemplo: usuario, visitante, admin

* *Terceira casa decimal:* representa a instância específica da funcionalidade, exemplo: cadastro, edição, exclusão

* *Core* - Requisitos importantes, mas não críticos

* *Edge* - Requisitos desejáveis, mas não essenciais

== Descrição geral do sistema

O sistema FairTech Vote e um sistema que procura facilitar a votação em feiras de ciências, o mesmo será
desenvolvido com a ideia de uma aplicação web API em uma intranet conectada a uma aplicação terminal por meio 
de totens, em termos de arquitetura o sistema está sendo planejado por meio de microserviços usando duas apis principais
uma responsavel pelo armazenamento de dados da feira tais como projetos e eventos tendo como foco a rápida leitura
dos mesmos e outra responsavel pela coleta e processamento dos votos, garantindo a integridade e segurança das informações, para isso será utilizado dois banco o couchbase agira na recuperação de dados com alta demanda de escrita como os votos e o cassandradb sera utilizado para consultas mais complexas e com alta demanda de leitura, tais como a apresentação dos projetos.

=== Descrição dos Usuarios

Os usuários que estão sendo projetados para o sistema FairTech Vote estão classificados em:

* *Visitantes:* Usuários que tem acesso a visualização de projetos e eventos, podendo votar nos projetos apresentados.

* *Organizadores:* Usuários responsáveis pela criação e gerenciamento dos eventos e projetos, podendo visualizar estatísticas de participação e votação.

=== Requisitos Funcionais:

* *[RF001] - Cadastro de Organizador:*
O sistema deve permitir o armazenamento de dados dos organizadores para gerenciamento dos eventos e projetos.
** *Ator:* Organizador
** *Prioridade:* Backbone
** *Entradas e pré-condições:* Para o organizador ser registrado o mesmo deve pertencer a uma instituição de ensino, 
previamente cadastrada e entrar com dados tais como nome, email para caso seja necessário recuperar senha, senha para
controle de acesso e instituição para determinar qual instituição o organizador está representando lembrando que o mesmo
poderá agir em mais de uma instituição
